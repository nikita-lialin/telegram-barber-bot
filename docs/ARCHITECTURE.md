# Архитектура

Документ описывает, как устроен бот, до начала разработки. Что бот делает и как проверять готовность, описано в [SCENARIOS.md](SCENARIOS.md).

Решения, помеченные **[решение]**, приняты по умолчанию и могут быть пересмотрены. Открытые вопросы собраны в конце документа.

## 1. Цели и принципы

1. **Данные и тексты отдельно от кода.** Мастера, услуги, график, адрес и галерея лежат в `data/*.json`, тексты интерфейса в `locales/*.ftl`. Владелец салона меняет цену или часы без правки TypeScript.
2. **Каждый раздел живёт в своём модуле.** Добавить раздел значит добавить папку в `src/features/` и одну строку регистрации.
3. **Логика не зависит от Telegram.** Расчёт «открыто сейчас», форматирование цен и сборка ссылок связи лежат в `src/domain/`, это чистые функции, которые легко тестировать.
4. **Бот не падает.** Данные проверяются при старте, ошибки во время работы ловятся централизованно, устаревшие кнопки и непонятный ввод возвращают пользователя в меню.
5. **Задел под онлайн-запись.** Доступ к данным идёт через интерфейсы (репозитории), чтобы JSON позже заменить на базу данных, не трогая разделы бота.

## 2. Стек

| Что | Выбор | Зачем |
|-----|-------|-------|
| Язык и рантайм | TypeScript (strict), Node.js 22 LTS | Требование проекта. |
| Фреймворк бота | [grammY](https://grammy.dev) | Требование проекта, хорошая типизация. |
| Мультиязычность | `@grammyjs/i18n` (формат Fluent `.ftl`) | Плюрализация, подстановки, хранение языка в сессии из коробки. |
| Сессии | `grammY session` + `@grammyjs/storage-file` | Язык переживает перезапуск без отдельной БД. **[решение]** |
| Валидация данных | `zod` | Схемы JSON и переменных окружения, типы выводятся из схем. |
| Дата и время | `date-fns` + `date-fns-tz` | Часовой пояс салона для «открыто сейчас». |

| Тесты | `vitest` | Быстрый, нативно работает с TypeScript и ESM. |
| Линт и формат | ESLint + Prettier | Единый стиль. |
| Сборка | `tsc` в `dist/`, для разработки `tsx watch` | Без лишних бандлеров. |

Каждый модуль в `features/` устроен одинаково:

```
features/services/
├── index.ts      # export const servicesFeature: Composer<BotContext>
├── handlers.ts   # обработчики callback-кнопок раздела
└── view.ts       # сборка текста и клавиатуры экрана (чистые функции)
```

`view.ts` не отправляет сообщения, а возвращает `{ text, keyboard, photo? }`. Это позволяет тестировать экраны без Telegram.

## 4. Модули и ответственность

| Модуль | Отвечает за | Не делает |
|--------|-------------|-----------|
| `index.ts` | Читает env, загружает данные, создаёт бота, запускает long polling, останавливает по SIGTERM. | Не содержит логики разделов. |
| `bot.ts` | Подключает middleware в фиксированном порядке и регистрирует модули. Принимает зависимости параметром, чтобы тесты подставляли свои. | Не читает файлы и env сам. |
| `config/` | Проверяет `BOT_TOKEN` и прочие переменные, падает с понятной ошибкой. | — |
| `domain/` | Типы и чистые функции бизнес-логики. | Не импортирует grammY. |
| `data/` | Загружает JSON, проверяет схемы и ссылки (у услуги указан существующий мастер, у фото существующая категория и файл). | Не знает про Telegram. |
| `i18n/` | Подключает переводы, определяет язык по умолчанию, хранит выбор в сессии. | — |
| `ui/` | Формат callback_data, общие кнопки, стратегия показа экрана. | Не знает про конкретные разделы. |
| `features/*` | Один раздел: обработчики и экраны. | Не обращается к другим разделам напрямую, только через `ui/callback.ts`. |
| `middleware/` | Ошибки и логирование. | — |

Порядок middleware в `bot.ts`:

1. `logger`
2. `privateOnly`: апдейты не из личного чата (группы, каналы) дальше не проходят, даже `/start`
3. `session` (хранилище языка)
4. `i18n`
5. модули `features/*` (start, menu, services, masters, gallery, schedule, location, booking, language, help)
6. `fallback` (последним: ловит всё, что не обработали выше)

Обработчик ошибок не входит в цепочку middleware: он регистрируется отдельно через `bot.catch(errorHandler)`.

## 5. Модель данных

Все данные описываются zod-схемами в `src/data/schemas.ts`, типы выводятся из схем (`z.infer`). Текст, который видит клиент, хранится сразу на двух языках.

```ts
type Locale = 'ru' | 'en';
type LocalizedText = Record<Locale, string>;   // { ru: '...', en: '...' }

type ServiceGroupId = 'men' | 'women' | 'kids' | 'coloring';

// Все id (мастеров, услуг, фото): ^[a-z0-9-]{1,20}$. Ограничение длины держит callback_data в 64 байтах.
type Id = string;

interface Contacts {              // схема требует хотя бы один канал
  whatsapp?: string;              // номер в формате E.164 без '+': '79990000001'
  phone?: string;                 // '+7 999 000-00-01'
  telegram?: string;              // username без '@'
  instagram?: string;             // username
}

interface Master {
  id: Id;                         // 'alexey', используется в callback_data
  name: LocalizedText;
  photo: string;                  // путь в assets/masters/
  specialization: LocalizedText;  // текст для карточки
  contacts: Contacts;
  contactHours: LocalizedText;    // 'Пн–Пт 10:00–19:00'
}
// Группы мастера не хранятся отдельно, а вычисляются из Service.masterIds.
// Так фильтр «мастер по задаче» не может разойтись с прайсом.

type Price =
  | { kind: 'fixed'; amount: number }      // 1500
  | { kind: 'from'; amount: number };      // от 4500, стоимость по сложности

interface Service {
  id: Id;                         // 'men-haircut'
  group: ServiceGroupId;
  title: LocalizedText;
  price: Price;
  durationMin: { min: number; max?: number };  // 45 или 120–240
  note?: LocalizedText;           // 'итог зависит от длины и сложности'
  masterIds: Id[];                // кто выполняет услугу, минимум один
}

interface ServiceGroup {
  id: ServiceGroupId;
  title: LocalizedText;
  emoji: string;
  order: number;
}

interface GalleryCategory { id: ServiceGroupId; title: LocalizedText; order: number }

interface GalleryItem {
  id: Id;
  category: ServiceGroupId;
  file: string;                   // путь в assets/gallery/
  caption: LocalizedText;
  masterId?: Id;                  // «работа Ольги» и кнопка записи к ней
}

type Weekday = 'mon' | 'tue' | 'wed' | 'thu' | 'fri' | 'sat' | 'sun';
interface TimeRange { open: string; close: string }   // '10:00', '20:00'

interface Schedule {
  timezone: string;               // 'Europe/Moscow'
  weekly: Record<Weekday, TimeRange | null>;          // null = выходной
  exceptions: Array<{             // предпраздничные и особые дни
    date: string;                 // '2026-12-31'
    hours: TimeRange | null;
    note?: LocalizedText;
  }>;
  specialDaysNote: LocalizedText; // 'Перед праздниками и по договорённости возможны доп. часы'
}

interface Business {
  name: LocalizedText;
  address: LocalizedText;
  mapLinks: { yandex?: string; google?: string };   // схема требует хотя бы одну ссылку
  geo?: { lat: number; lon: number };               // нужно, если включим sendVenue
  entranceHint: LocalizedText;
  entrancePhoto: string;          // путь в assets/location/, обязателен по карте экранов
  contacts: Contacts;             // общий контакт салона для варианта «Любой мастер»
  currency: 'RUB';
}
```

Пример `data/services.json` (фрагмент):

```json
{
  "groups": [
    { "id": "men", "emoji": "💇‍♂️", "order": 1, "title": { "ru": "Мужские", "en": "Men" } }
  ],
  "services": [
    {
      "id": "coloring-full",
      "group": "coloring",
      "title": { "ru": "Окрашивание", "en": "Coloring" },
      "price": { "kind": "from", "amount": 4500 },
      "durationMin": { "min": 120, "max": 240 },
      "note": { "ru": "Итог зависит от длины и сложности", "en": "Final price depends on length and complexity" },
      "masterIds": ["olga"]
    }
  ]
}
```

**Проверки при старте (`data/loader.ts`):**
- каждый файл соответствует схеме;
- `id` уникальны внутри своей коллекции (группы отдельно, услуги отдельно), id соответствуют `^[a-z0-9-]{1,20}$`;
- `masterIds`, `masterId`, `group`, `category` ссылаются на существующие записи;
- у каждого мастера и у салона есть хотя бы один канал связи, у салона хотя бы одна ссылка на карту;
- каждый мастер выполняет хотя бы одну услугу;
- файлы фото из `photo`, `file`, `entrancePhoto` существуют, это JPEG или PNG не больше 5 МБ (лимит Telegram для фото 10 МБ, сумма сторон до 10 000 px);
- у каждой `LocalizedText` заполнены оба языка;
- критерии приёмки: ровно 4 мастера, 4 группы, не меньше 8 фото в 3+ категориях (проверяется тестом, а не при старте, чтобы бот можно было запустить и с неполной галереей).

Если проверка не прошла, бот не запускается и пишет в лог, какой файл и какое поле неверны.

**Фото.** Файлы лежат в `assets/`. Перед коммитом их ужимают до ~1280 px по длинной стороне (скрипт `npm run optimize-assets` на `sharp`), поэтому лимиты Telegram не достигаются. При первой отправке Telegram возвращает `file_id`, бот кэширует его в памяти (`Map<путь, file_id>`) и дальше шлёт фото по `file_id`, без повторной загрузки. Кэш не сохраняется на диск: после перезапуска первая отправка снова загрузит файл, это дёшево.

## 6. Мультиязычность (i18n)

Два источника текста:

| Что | Где | Пример |
|-----|-----|--------|
| Интерфейс: кнопки, заголовки, подсказки, ошибки | `locales/ru.ftl`, `locales/en.ftl` | `menu-services = 💈 Услуги и цены` |
| Контент: имена, услуги, подписи, адрес | `data/*.json`, поле `LocalizedText` | `"title": { "ru": "Стрижка", "en": "Haircut" }` |

Пример `locales/ru.ftl`:

```ftl
menu-title = Главное меню
menu-services = 💈 Услуги и цены
btn-back = ← Назад
btn-main-menu = 🏠 Главное меню
price-fixed = { $amount } ₽
price-from = от { $amount } ₽
schedule-open-now = 🟢 Сейчас открыто до { $close }
schedule-closed-now = 🔴 Сейчас закрыто, откроемся { $next }
```

**Правила:**
- В коде нет строк для пользователя: только `ctx.t('ключ', параметры)` и `pick(localizedText, ctx.locale)`.
- Ключи именуются по разделу: `menu-*`, `services-*`, `masters-*`, `gallery-*`, `schedule-*`, `location-*`, `booking-*`, `errors-*`.
- Тест проверяет, что наборы ключей в `ru.ftl` и `en.ftl` совпадают, и что каждый ключ, вызванный в коде, есть в обоих файлах.
- Список команд (`/start`, `/menu`, `/help`) регистрируется через `setMyCommands` для каждого языка, чтобы описания в меню Telegram тоже переводились.

**Выбор и хранение языка:**
1. Язык хранится в сессии пользователя (`session.locale`).
2. При первом `/start` языка в сессии нет: язык берётся из `ctx.from.language_code` (`ru*` → `ru`, иначе `en`), записывается в сессию, и бот сразу показывает приветствие и главное меню на этом языке. Вопроса про язык нет. **[решение Никиты]**
3. Если язык определился неверно, его меняют пунктом «🌐 Язык» в главном меню (он виден на первом экране).
4. Пункт меню «🌐 Язык» меняет `session.locale` и перерисовывает текущее сообщение на новом языке.
5. Если сессия по какой-то причине пустая (например, удалили файл хранилища), язык определяется заново так же, как при первом входе.

**Хранилище сессии.** `@grammyjs/storage-file` пишет данные в папку `sessions/` (в Docker это volume). В сессии только `{ locale }`, никаких персональных данных. Ключ сессии: id пользователя. Интерфейс хранилища в grammY одинаковый, поэтому переход на Redis или базу позже меняет одну строку в `bot.ts`.

## 7. Навигация и callback-кнопки

### Один экран, одно сообщение

Бот ведёт пользователя в одном сообщении: нажатие кнопки редактирует текущее сообщение, а не присылает новое. Чат не засоряется, «Назад» работает естественно. **[решение]**

Ограничение Telegram: текстовое сообщение нельзя превратить в сообщение с фото через редактирование. Поэтому `ui/render.ts` выбирает способ показа:

| Было | Стало | Действие |
|------|-------|----------|
| текст | текст | `editMessageText` |
| фото | фото | `editMessageMedia` (смена фото и подписи) |
| текст ↔ фото | | отправить новое сообщение, и только после успешной отправки удалить старое |
| команда `/start`, `/menu` | любое | отправить новое сообщение |

Ошибку Telegram `message is not modified` (повторное нажатие той же кнопки) рендер молча игнорирует.

### Формат callback_data

Telegram ограничивает `callback_data` 64 байтами, поэтому формат короткий и строгий:

```
<раздел>:<действие>[:<параметр>...]
```

| Кнопка | callback_data |
|--------|---------------|
| Главное меню | `m` |
| Услуги, список групп | `s` |
| Услуги, группа «Мужские» | `s:g:men` |
| Мастера, список | `ms` |
| Мастера, фильтр по группе | `ms:f:coloring` |
| Карточка мастера | `ms:c:olga` |
| Позвонить мастеру | `ms:call:olga` |
| Галерея, категории | `g` |
| Галерея, фото №3 в категории | `g:p:women:3` |
| График | `sch` |
| Адрес | `loc` |
| Запись, выбор мастера | `b` |
| Запись из экрана услуги | `b:s:coloring-full` (выбор мастера среди тех, кто делает услугу) |
| Запись к мастеру | `b:m:olga` (или `b:m:any`) |
| Запись к мастеру на услугу | `b:m:olga:coloring-full` |
| Если не отвечает | `b:nr:olga` |
| Выбор языка | `l:ru`, `l:en` |
| Пустая кнопка (счётчик «3/8») | `noop` |

`ui/callback.ts` содержит типизированные функции `encode(route)` и `decode(data)`. Модули не собирают строки вручную, поэтому опечатка в маршруте ловится компилятором. Выбранная услуга едет в самом callback, а не в сессии, поэтому кнопки работают и после перезапуска бота. Самый длинный маршрут `b:m:<id>:<id>` при id до 20 символов занимает 46 байт; тест проверяет лимит 64 байта на реальных данных.

Регистрация в модуле выглядит так (иллюстрация, не финальный код):

```ts
composer.callbackQuery(/^s:g:(\w+)$/, async (ctx) => { ... });
```

### «Назад» без истории

Стек переходов не храним. У каждого экрана один известный родитель, и кнопка «Назад» ведёт на него: карточка мастера → список мастеров → главное меню. Это проще и устойчиво к перезапускам.

### Кнопки связи

- **WhatsApp:** URL-кнопка `https://wa.me/<номер>?text=<готовый текст>`.
- **Telegram:** URL-кнопка `https://t.me/<username>`. Подставит ли Telegram готовый текст, зависит от клиента, поэтому текст сообщения также показывается в экране записи, чтобы его можно было скопировать.
- **Звонок:** Telegram не поддерживает ссылки `tel:` в inline-кнопках. Кнопка «Позвонить» присылает карточку контакта (`sendContact`): в ней есть кнопка звонка. Номер также виден текстом в карточке мастера, Telegram делает его кликабельным.
- **Карта:** URL-кнопки на Яндекс и Google Карты, плюс `sendVenue` с координатами из `business.geo`, чтобы карта открылась прямо в Telegram (по желанию, см. вопросы).

Готовый текст сообщения собирается в `domain/contacts.ts` из шаблона в `.ftl`, например: «Здравствуйте! Хочу записаться к Ольге на окрашивание». Если услуга не выбрана, используется общий шаблон без неё.

### Сценарий «нет ответа»

Отдельного ожидания и таймеров нет. На экране записи под каналами есть кнопка «Мастер не отвечает?». Она показывает часы связи мастера, другие каналы этого мастера и общий контакт салона.

## 8. Ошибки и непонятный ввод

### Ошибки при старте
- Нет или неверный `BOT_TOKEN`, ошибки в `data/*.json`, нет файлов фото: процесс завершается с кодом 1 и понятным сообщением в логе. Лучше не запуститься, чем показать клиенту пустой прайс.

### Ошибки во время работы
`bot.catch` в `middleware/error-handler.ts`:

| Ошибка | Реакция |
|--------|---------|
| `GrammyError` «message is not modified» | Игнорировать. |
| `GrammyError` «message to edit not found» / «message can't be edited» | Отправить экран новым сообщением. |
| `GrammyError` 403 (пользователь заблокировал бота) | Записать в лог на уровне `info`, ничего не отправлять. |
| `GrammyError` 429 (лимит запросов) | Подключить плагин `@grammyjs/auto-retry`, он сам повторит запрос. |
| `HttpError` (сеть) | Лог `warn`, grammY продолжит polling. |
| Любая другая | Лог `error` с id апдейта, пользователю: «Что-то пошло не так, вот меню» и кнопка меню. |

Каждый обработчик кнопки вызывает `answerCallbackQuery`, иначе у пользователя крутятся «часики». Это делается в одном месте: обёртка в `ui/` вызывает его после обработчика, даже если обработчик упал.

### Непонятный ввод (`features/fallback`)
- Текст, стикер, фото, голосовое, документ: короткая подсказка «Я понимаю только кнопки меню» и кнопка «Главное меню».
- Чтобы не спамить, подсказка отправляется не чаще раза в 30 секунд для одного пользователя, остальные сообщения игнорируются. **[решение]**
- Устаревшая кнопка (callback, который не узнал ни один модуль, или ссылка на удалённого мастера): `answerCallbackQuery` с текстом «Кнопка устарела» и показ главного меню.
- Бот работает только в личных чатах: middleware `privateOnly` отсекает группы и каналы до всех модулей.

## 10. Запуск и деплой

### Переменные окружения (`.env.example`)

```
BOT_TOKEN=            # токен от @BotFather
NODE_ENV=development  # development | production
LOG_LEVEL=info
SESSION_DIR=./sessions
```

Часовой пояс салона хранится в `data/schedule.json`, а не в env: это свойство бизнеса, а не сервера.

### Команды

| Команда | Что делает |
|---------|------------|
| `npm run dev` | `tsx watch --env-file=.env src/index.ts`, перезапуск при изменениях. |
| `npm run build` | `tsc` в `dist/`. |
| `npm start` | `node --env-file-if-exists=.env dist/index.js`. В Docker и на хостинге переменные задаются окружением, файл `.env` не нужен. |
| `npm test` | `vitest run`. |
| `npm run lint`, `npm run typecheck` | Проверки для CI. |
| `npm run validate-data` | Проверить `data/*.json` и фото без запуска бота. Удобно после правки прайса. |
| `npm run optimize-assets` | Ужать фото в `assets/` перед коммитом. |

### Режим получения апдейтов
Long polling. **[решение]** Не нужен домен и HTTPS, работает на любом сервере и локально. Webhook имеет смысл, если позже понадобится serverless-хостинг, тогда добавится второй файл входа `src/webhook.ts`, логика бота не меняется.

### Деплой
- `Dockerfile` в два этапа: сборка (`npm ci`, `tsc`) и запуск (`node:22-alpine`, только `dist/`, `data/`, `locales/`, `assets/`, prod-зависимости).
- Папка `sessions/` монтируется как volume, чтобы язык пользователей не терялся при обновлении.
- Хостинг: нужен реальный деплой. **[решение Никиты]** Выбран Fly.io: один инстанс, volume под `sessions/`, секрет `BOT_TOKEN` через `fly secrets`. VPS с Docker Compose остаётся запасным вариантом, код от площадки не зависит.
- CI/CD: GitHub Actions после прохождения тестов на `main` собирает образ и выкатывает его (для Fly.io `flyctl deploy --strategy immediate`). Токен деплоя хранится в GitHub Secrets.
- Graceful shutdown: по `SIGTERM`/`SIGINT` вызывается `bot.stop()`, чтобы не терять апдейты при перезапуске.
- Ровно один экземпляр бота. Telegram отдаёт long polling только одному получателю, второй получит ошибку 409. Поэтому деплой идёт по схеме «остановить старый, запустить новый» (`docker compose up -d` с одним сервисом, на Fly.io стратегия `immediate` и один инстанс). Простой при обновлении несколько секунд, апдейты за это время Telegram хранит и отдаст после старта.
- Обновить прайс или график: правка JSON → коммит → пересборка образа. Горячая перезагрузка данных без рестарта не нужна для этой версии.

## 11. Задел под онлайн-запись

В этой версии онлайн-записи нет, но архитектура готова к ней без переписывания разделов.

1. **Репозиторий вместо прямого чтения JSON.** Модули получают данные через интерфейс:
   ```ts
   interface CatalogRepository {
     getMasters(group?: ServiceGroupId): Promise<Master[]>;   // с фильтром «мастер по задаче»
     getMaster(id: string): Promise<Master | undefined>;
     getServiceGroups(): Promise<ServiceGroup[]>;             // отсортированы по order
     getServices(group?: ServiceGroupId): Promise<Service[]>;
     getService(id: string): Promise<Service | undefined>;
     getGalleryCategories(): Promise<GalleryCategory[]>;      // только непустые, по order
     getGallery(category: ServiceGroupId): Promise<GalleryItem[]>;
     getSchedule(): Promise<Schedule>;
     getBusiness(): Promise<Business>;
   }
   ```
   Сейчас реализация читает JSON в память при старте. Позже появится реализация на PostgreSQL или SQLite, а модули не изменятся. Методы асинхронные уже сейчас, чтобы не менять сигнатуры потом.

2. **Канал записи как стратегия.** Модуль `booking` спрашивает у интерфейса, как записать клиента:
   ```ts
   interface BookingProvider {
     getOptions(masterId: string | 'any', serviceId?: string): Promise<BookingOption[]>;
   }
   // BookingOption: { kind: 'link', channel: 'whatsapp' | 'telegram', url } | { kind: 'contact', phone }
   ```
   Сейчас `ExternalLinksBookingProvider` возвращает ссылки. Позже `OnlineBookingProvider` добавит `{ kind: 'slots', ... }`, и модуль покажет календарь окон.

3. **Стабильные id.** У мастеров и услуг строковые id (`olga`, `coloring`), которые не меняются при переименовании. Они станут ключами в базе и в записях клиентов.

4. **Длительность услуг уже в модели.** Она нужна для расчёта свободных окон.

5. **Сессия расширяемая.** Сейчас в ней только `locale`. Позже туда добавится черновик записи (выбранные мастер, услуга, дата) для пошагового диалога, например через плагин `@grammyjs/conversations`.

6. **Следующие шаги после этого проекта:** хранилище записей, календарь окон, уведомления мастеру, напоминания клиенту, админ-команды для мастеров, оплата, CRM.

## 12. Открытые вопросы

Решено:
- **Звонок:** «Позвонить» присылает карточку контакта.
- **Первый вход:** сразу меню на языке из настроек Telegram, без вопроса.
- **Instagram:** четвёртый канал связи (WhatsApp, звонок, Telegram, Instagram), ссылка `https://instagram.com/<username>`.
- **Деплой:** реальный, Fly.io или VPS.

Принято по умолчанию (Никита делегировал выбор):
1. **Хранение языка:** файловое хранилище сессий. Переход на Redis или SQLite позже меняет одну строку.
2. **Навигация:** редактирование одного сообщения.
3. **Карта:** только ссылки на Яндекс и Google Карты, без `sendVenue`. Поле `business.geo` остаётся необязательным на будущее.
4. **Площадка деплоя:** Fly.io (один инстанс, volume под `sessions/`, секреты через `fly secrets`).
